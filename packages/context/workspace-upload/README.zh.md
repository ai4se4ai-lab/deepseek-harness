# `@deepseek-ai/dsh-workspace-upload`

[English](README.md) | 中文

用户将文件上传到会话工作区的宿主服务。编辑器的 `/upload` 命令把所选文件以规范 base64 形式发送到一元 Remote 方法 `workspaceUpload/put`（在服务定义上以 `@Remote` 标注，agent 由传输身份解析）。该服务解码载荷，执行可配置的字节上限（`maxBytes`，默认 10 MiB），应用严格的基名策略（不含路径分隔符、不含指向上级目录的 `..`、不含控制字符），以 ` (n)` 后缀消解重名冲突，并在 `realpath` 守卫（确保目标位于会话工作区内）之下把文件写入 `<会话 cwd>/files/`。

写入成功后，服务发出宿主内部的单向 cordis 事件 `workspace/file-added`，以便文件引用发现丢弃其缓存的工作区索引，立即将新文件提供给 `@files/…` 补全。

## 模型体验

间接。该服务本身从不新增请求 token 或会话日志内容：上传的文件只有在被作为普通的 `@files/<name>` 路径引用命名、且模型调用其 `read` 工具时才对模型可见——与其他工作区文件完全一致。

#### KV 缓存影响

无；本包既不组装也不发送提供方请求。

## 已知限制与后续工作

- **无上传历史** —— 服务写入文件后即返回；它不记录上传内容，也不提供列举或删除操作（工作区目录浏览器才是权威）。
- **整体载荷传输** —— 文件以单个 base64 字符串跨线传输，无分片或断点续传，因此字节上限同时也是实际的单请求体积上限。
- **仅在单次调用内消解冲突** —— 两个客户端并发上传同名文件时会在 `wx` 创建标志上竞争；失败方会针对下一个空闲的 ` (n)` 名称重试。
