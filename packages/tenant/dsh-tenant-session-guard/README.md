# @mindportalix/dsh-tenant-session-guard

Tenant-scoping wrapper over the `ctx.sessionController`, `ctx.workspaceController`, and `ctx.directoryPickerController` Typert Remote Services, for the single shared DSH container behind the MindPortalix reverse proxy. Requires `ctx.tenantContext` (`@mindportalix/dsh-tenant-context`) as the sole source of tenant identity, and `ctx.sessions` to resolve a session id to its recorded `cwd`.

On activation, it monkey-patches the plain instance methods `ctx.sessionController.{list,search,create,selectModel,rename,fork,prompt,attachment,updateQueue,cancel,page,control}`, `ctx.workspaceController.{create,rename,delete,insertBefore,insertSessionBefore,archiveSession,follow}`, and `ctx.directoryPickerController.{list,createDirectory}`, restoring the originals on disposal. The Typert Gateway resolves the owning Service and looks up the invoked method by name fresh on every call (`packages/api/gateway/src/index.ts`'s `prepareInvocation`, never a reference captured once at registration time), so this later reassignment on each live singleton is observed by every subsequent Remote dispatch — the same pattern this package used over the predecessor `ctx.apiProxy` before upstream's Typert Remote migration replaced it.

- `session.create`: an explicit `cwd` or `workspaceId` must resolve under the caller's `$DSH_HOME/tenants/<tenantId>` root, or the call is rejected (`mindportalix/tenant-path-invalid` / `workspace/not-found`); an omitted `cwd`/`workspaceId` defaults to the tenant root explicitly (never the process's shared default project directory).
- `session.list` / `session.search`: results are filtered to sessions whose `cwd` falls under the caller's tenant root (a session with no recorded `cwd` is dropped, not shown — fail closed); `search` reuses the filtered `session.list` as its visibility allowlist, since search results carry no `cwd` of their own.
- `session.selectModel` / `rename` / `fork` / `prompt` / `attachment` / `updateQueue` / `cancel` / `page`: guarded by the targeted (or, for `page`, the durable address's) `sessionId` resolving to a tenant-visible session (via the same allowlist as `session.list`), or rejected with `session/not-found` — the same code a genuinely unknown id produces, so existence is never disclosed cross-tenant. `fork`'s child inherits the source session's `cwd` verbatim, so proving the source is tenant-owned is sufficient.
- `workspace.create`: the `path` must resolve under the tenant root.
- `workspace.rename` / `delete` / `insertBefore` / `insertSessionBefore`: the targeted `workspaceId` (and `beforeWorkspaceId` where present) must resolve to a tenant-visible workspace, or the call is rejected with `workspace/not-found`.
- `workspace.archiveSession`: ownership is proved by workspace membership (a workspace accounts every session it owns, including archived ones); a session owned by no tenant-visible workspace is rejected with `session/not-found`.
- `directoryPicker.list` / `createDirectory`: the "Add workspace" folder browser's backend, otherwise entirely unaware of tenant scoping. An explicit `path` must resolve under the tenant root or the call is rejected with `mindportalix/tenant-path-invalid`; `list`'s omitted `path` defaults to the tenant root explicitly, and every answer's `home` field is rewritten to the tenant root with `crumbs` cut to start there, so the browser's own "Home" shortcut and breadcrumb trail never point above it.

Every wrapped RPC method (everything above except the two streams below) calls `ctx.tenantContext.current()` first; with no tenant identity bound, it throws the `mindportalix/tenant-required` `RemoteError` rather than proceeding unscoped. This is safe because every one of these methods is dispatched through `@deepseek-ai/dsh-client-connection`'s `/api` HTTP route, which binds the trusted proxy's tenant id around the whole request with `ctx.tenantContext.run(...)`.

## Known gap — Remote streams

`session.follow`, `session.control`, and `workspace.follow` are `@Remote({ mode: 'stream' })` methods opened over API Gateway's single multiplexed `/api/remote.mux` WebSocket (`packages/api/gateway`), not the `/api` HTTP route. This fork has not verified that `ctx.tenantContext` is bound around that WebSocket connection's lifetime — the predecessor `websocket-downlink.ts` this package relied on for that binding was removed by the upstream Typert Remote migration, and no replacement extension point was found in `packages/api/gateway` or `packages/host/webserver`; modifying either without the ability to test against a live composed app was judged riskier than leaving this narrower, pre-existing gap for follow-up work.

- `session.control` and `workspace.follow` are wrapped to filter their frames by tenant *opportunistically*: when `ctx.tenantContext.current()` resolves, frames are scoped exactly like the RPC methods above; when it does not (today's expected case), every frame passes through unfiltered rather than the stream being dropped. Fixing the WebSocket-side tenant binding later makes both fully scoped with no further change here.
- `session.follow` is not wrapped at all (its frames are per-session Session-log content, always opened for one already-`page`/`prompt`-guarded session id — the higher-value target was the streams that carry cross-session summaries).
- Left unresolved, this is a **live-push metadata leak, never a data-read or data-write path**: a tenant may observe another tenant's session ids, `cwd`, and running/blank/queue/job state over `session.control` and `workspace.follow`. Every RPC method that could actually *act* on a foreign id — `session.rename`/`prompt`/`attachment`/`page`/`selectModel`/`fork`/`updateQueue`/`cancel`, every `workspace.*` mutation, `directoryPicker.*` — remains fully guarded above and rejects with `session/not-found` / `workspace/not-found` / `mindportalix/tenant-path-invalid` regardless of this gap.
- The forwarded Cordis-event broadcast (`packages/api/remotes` registers the application's event source; `packages/api/gateway`'s `broadcastRemoteEvent` fans it out to every connected browser tab — `api-session/added` and similar) has the same narrow-leak shape, but no per-client hook exists today to filter it at all (the fan-out has no per-client filter parameter). Closing it needs a small Gateway-side change; tracked as follow-up work, not attempted here for the same live-app-testing reason as the WebSocket tenant binding above.

## Model Experience

This package has no model, token, or KV-cache effect: it is a Remote-Service wrapper with no system-prompt, tool, or session-log surface.

## Known Limitations and Deferred Work

- `workspace.archiveSession` rejects every session with no owning tenant-visible workspace, including a caller's own genuinely ungrouped session — deliberately conservative (fail closed) rather than allowing an unverified session through.
- The `danger-full-access` sandbox-mode escalation is not interceptable here: `session.create`'s wire payload carries no mode field at all, and that mode is reached only through a selected permission preset (`@deepseek-ai/dsh-permission-presets`). `deploy/tenant-isolation.cordis.patch.yml` closes this path at the composition level instead, by dropping the `danger-full-access` preset from the `permission` row.
- See "Known gap — Remote streams" above for the WebSocket-mux and forwarded-event fan-out gaps.
