# @mindportalix/dsh-tenant-session-guard

Tenant-scoping wrapper over `ctx.apiProxy`'s session, workspace, directory-browse, and event-stream RPC methods, for the single shared DSH container behind the MindPortalix reverse proxy. Requires `ctx.tenantContext` (`@mindportalix/dsh-tenant-context`) as the sole source of tenant identity, and `ctx.sessions` to resolve a session id to its recorded `cwd` while filtering stream frames.

On activation, it monkey-patches the plain closures `ctx.apiProxy.sessions.*`, `ctx.apiProxy.workspace.*`, `ctx.apiProxy.host.{listDirectory,createDirectory}`, and `ctx.apiProxy.events.{mux,host}`, restoring the originals on disposal:

- `session.create`: an explicit `cwd` or `workspaceId` must resolve under the caller's `$DSH_HOME/tenants/<tenantId>` root, or the call is rejected (`tenant-path-invalid` / `workspace-not-found`); an omitted `cwd`/`workspaceId` defaults to the tenant root explicitly (never the process's shared default project directory).
- `session.list` / `session.search`: results are filtered to sessions whose `cwd` falls under the caller's tenant root (a session with no recorded `cwd` is dropped, not shown — fail closed); `search` reuses the filtered `session.list` as its visibility allowlist, since search results carry no `cwd` of their own.
- `workspace.list`: `items` are filtered by `path`; `archivedSessionIds` is filtered to ids that appear in a tenant-visible workspace's `sessionIds` account (archived sessions carry no path of their own).
- `workspace.create`: the `path` must resolve under the tenant root.
- `workspace.rename` / `delete` / `insertBefore` / `insertSessionBefore`: the targeted `workspaceId` (and `beforeWorkspaceId` where present) must resolve to a tenant-visible workspace, or the call is rejected with `workspace-not-found` — the same code a genuinely unknown id produces, so existence is never disclosed cross-tenant.
- `workspace.archiveSession`: ownership is proved by workspace membership (a workspace accounts every session it owns, including archived ones); a session owned by no tenant-visible workspace is rejected with `session-not-found`.
- `host.listDirectory`: the "Add workspace" folder browser's backend, otherwise entirely unaware of tenant scoping (it lists `os.homedir()` — the container OS user's home, e.g. `/home/node` — by default and lets a caller browse anywhere the process can read). An explicit `path` must resolve under the tenant root or the call is rejected with `tenant-path-invalid`; an omitted `path` defaults to the tenant root explicitly, and every answer's `home` field is rewritten to the tenant root with `crumbs` cut to start there, so the browser's own "Home" shortcut and breadcrumb trail never point above it.
- `host.createDirectory`: the browser's "New folder" action; the parent `path` must resolve under the tenant root or the call is rejected with `tenant-path-invalid`.
- `events.mux`: the aggregated per-session downlink. `stream/error` always passes; every other frame carries a `sessionId` and is forwarded only when that session is visible to the caller's tenant (already tracked as owned by this stream, or an attached session whose `cwd` is under the tenant root — a session with no resolvable `cwd` is dropped, fail closed).
- `events.host`: the host-level downlink. `stream/error` always passes. `host/remote-event` passes for the still-process-global planes (settings/models/preset/command changes) but is **dropped** for `credentials/reference-updated`, since `@mindportalix/dsh-tenant-credentials-local` makes every credential document per-tenant and the frame carries only the ref name, no originating tenant to scope against (a tenant's own second tab picks up its key change on reload). `host/session-added` is forwarded only if its `cwd` is under the tenant root (then the session id is tracked); `host/session-status` / `host/agent-error` only for a visible session; `host/session-removed` only for a session this stream already forwarded (so the tenant still learns its own session ended). `host/workspace-changed` is forwarded only for a workspace under the tenant root (then its id and member session ids are tracked); `host/workspace-removed` only for a workspace this stream forwarded; `host/workspace-order-changed` and `host/archived-sessions-changed` are rewritten to the caller's own ids. An unrecognised (merge-extensible) `HostFrame` variant is dropped.

Both stream wrappers read the connection's tenant with `ctx.tenantContext.current()` at open time — `@deepseek-ai/dsh-client-connection`'s WebSocket carrier opens each downlink inside `ctx.tenantContext.run(tenantId, …)`, so the id is bound there and across every generator resumption. A stream opened with no tenant bound yields nothing (fail closed).

Every wrapped RPC method calls `ctx.tenantContext.requireCurrent()` first; with no tenant identity bound, it returns the structured `tenant-required` RPC error rather than proceeding unscoped.

## Model Experience

This package has no model, token, or KV-cache effect: it is an RPC-gateway wrapper with no system-prompt, tool, or session-log surface.

## Known Limitations and Deferred Work

- `workspace.archiveSession` rejects every session with no owning tenant-visible workspace, including a caller's own genuinely ungrouped session — deliberately conservative (fail closed) rather than allowing an unverified session through.
- The `events.mux` / `events.host` frame filters resolve a session's `cwd` through `ctx.sessions.get(id)` (attached sessions only). A frame for a session that has already been disposed, so its `cwd` can no longer be read, is dropped unless this stream previously forwarded that id — which the wrappers track precisely so a tenant still receives its own `host/session-removed`. A brand-new session's `host/session-status(running:true)` is preceded by its `host/session-added` (carrying `cwd`), so ordering already covers the common case.
- `host/remote-event` frames are forwarded unfiltered for the settings, model-adapter, agent-preset, and command planes, which are still process-global in this shared container. `credentials/reference-updated` is the one exception — dropped, because `@mindportalix/dsh-tenant-credentials-local` scoped that plane per-tenant. If any of the remaining planes later becomes tenant-scoped, its event needs the same treatment; scoping (rather than dropping) would need the frame to carry the originating tenant.
- The `danger-full-access` sandbox-mode escalation is not interceptable here: `session.create`'s wire payload carries no mode field at all (see `packages/host/apiproxy/src/api/sessions.schema.ts`), and that mode is reached only through a selected permission preset (`@deepseek-ai/dsh-permission-presets`). `deploy/tenant-isolation.cordis.patch.yml` closes this path at the composition level instead, by dropping the `danger-full-access` preset from the `permission` row.
